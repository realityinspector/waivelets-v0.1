Paste text. Get back: AI or human, and which model.

A two-stage cascade. First stage flags AI vs human at ~92.7% accuracy. If AI, second stage names the most likely of 8 frontier models at ~88.5% leave-one-out accuracy. Combined: ~82% on AI text that gets correctly flagged AND named.

How well it works

8-way model identification, leave-one-document-out across 96 generations from 8 LLMs (Claude Sonnet 4 / 4.5, Haiku 4.5, GPT-4-turbo / 4o / 5, Gemini 2.5 Pro, Llama 3.3 70B). Permutation null sits at 12% (8-way chance). The shipped cascade uses the green adversarial topic-debiased basis bar — 48 dimensions, within 1pp of the raw-embedding upper bound.

Confusion matrix from the prior 76% spectrometer (haven't yet re-rendered for the 88.5% adversarial result — when we do, the diagonal will be tighter, but the family-confusion structure should stay roughly the same).

Easiest to identify: claude-sonnet-4 and gpt-4-turbo (11/12 each). Hardest: gpt-5, gemini-2.5-pro, llama-3.3 — confused with each other (likely a "reasoning-trained + open-source" stylistic cluster).

How it works — the spectrometer flashlight

Each text gets shone on by a small zoo of bases. Each basis is a 384×K matrix that projects MiniLM sentence embeddings into K interpretable axes, then we aggregate per-document features (mean projection + |mean| projection + basin visit histogram across K attractors). Different bases see different structure:

  • Gutenberg basis (v0.1) — 26 wavelet-derived axes from 100 human-literary texts. Sees structural categories of human writing.
  • LLM-PCA basis (v0.2) — 26 PCA axes from 3 084 LLM-generated sentences. Sees variance directions of LLM output space.
  • LLM-wavelet basis (v0.3) — 26 wavelet axes from the same corpus, capturing multi-scale sequential structure that PCA misses.
  • Adversarial basis (v0.3, shipped) — 16 axes from a triplet-loss network with two heads: maximize model-discrimination, minimize prompt-discrimination via gradient reversal. Removes topic confound from the projection.

The bases are nearly perpendicular to each other (mean |cos| ≈ 0.11), so stacking them adds rather than overlaps. Adversarial alone wins because it's the only basis explicitly trained on the labels we care about.

The stacking lesson

Concatenating bases helps only when there's enough data to estimate the joint covariance. At n=96 (12 per class × 8 classes), stacking past ~150 dimensions starts hurting. Adversarial alone (48-D) → 88.5%. Adversarial + everything else (273-D) → 79.2%. Picking the right single label-aware basis beats piling on auxiliaries. With more data, the story probably flips — v0.4 hypothesis.

Calibration honesty

The /identify tool returns top-3 candidate models with probability percentages. Those percentages are rank-ordering, softened with a fixed temperature (T=30) so the runners-up are legible. They are not Platt-calibrated: a "78%" call isn't literally 78% likely to be right. Read the bars as a leaderboard — the spread between top and runner-up tells you how decisive the call was in the LDA's decision space.

Honest calibration on a proper held-out set is a v0.4 follow-up. Until then, trust the rank more than the percentage.

Caveats

  • n = 12 per model. Enough for family-level signal, marginal for sibling models (sonnet-4 vs sonnet-4.5 still confusable).
  • Same 12 prompts per model. Per-prompt content variance still dominates per-model voice variance. Unsupervised clustering finds zero model structure; LDA only works because we hand it labels. The adversarial debiasing was specifically designed to fight this.
  • Temperature 0.7 at generation time. Varied temps widen intra-model spread.
  • Reasoning traces invisible. Only final message.content is captured. CoT-heavy models lose part of their signature.
  • MiniLM-conditioned. The discrimination is partly a fingerprint of MiniLM reading the models. Different embedder → different separation.

Reproduce

Everything in github.com/realityinspector/waivelets-v0.1:

  • exp/run.py, exp/retry.py, exp/more_free.py — OpenRouter generation
  • exp/extract_26d.py, exp/fit_llm_basis.py — PCA basis + features
  • exp/wavelet_basis.py, exp/wavelet_eval.py — wavelet basis (v0.1 methodology applied to LLM corpus)
  • exp/lda_basis.py, exp/contrastive_basis.py, exp/adversarial_basis.py — label-aware bases
  • exp/expansion_eval.py — strict nested LOO across all conditions with 100-permutation null
  • exp/train_deploy.py — trains the deployable adversarial artifacts (web/assets/identify_artifacts.npz)
  • exp/per_sent_vote_v2.py — per-sentence classification + majority vote (the informative negative)
